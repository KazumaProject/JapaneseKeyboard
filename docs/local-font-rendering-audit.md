# Local font rendering audit

## Scope and rules

The local font is an optional, process-local keyboard font. A missing font leaves every target on its existing Android/theme typeface. Import previews are rendered only by the Local Font settings samples; they do not update IME views. Pressing **Apply** publishes one new `KeyboardFontSnapshot` from `LocalFontRepository`. The IME service collects that state and updates the current main, floating, candidate, composing-guide, dictionary, physical-toolbar, and split-keyboard surfaces. New renderer instances take the current process snapshot when constructed, and setters retain it for later popup or adapter content.

`KeyboardFontApplicator` records the original typeface independently for each `TextView` and `Paint`, applies the imported family with that target's original bold/italic style, and restores that exact baseline when the snapshot's typeface is `null`. If a theme changes the typeface while a custom font is active, the next font update records that new themed typeface as the baseline. Existing size/color/layout spans continue to affect their own ranges; there are no `TypefaceSpan` overrides in the audited runtime keyboard modules.

## Drawing-free intermediaries

These coordinate content or move existing views but do not render keyboard text themselves: `LocalFontRepository` owns import and state; `ComposingGuideController` and `ComposingGuideWindow` forward state to their view; `SplitKeyboardController` forwards pane behavior while the service styles the bound pane; adapters store the latest snapshot for later binds; `FloatingPanelFrame` styles only its own title and leaves pane content to its renderer/adapter. `IMEService` also coordinates its transient popup windows and applies font-aware popup content immediately before display. An intermediary is not treated as a text-render target unless it owns a TextView/Paint or explicitly forwards to one.

## Intentional non-IME exceptions

The settings-only illustration views `CircularFlickPreviewView`, `PopupStylePreviewViews`, `KeyboardThemePreviewView`, and `custom_keyboard/ui/FlickGridEditorView` retain their existing illustrative/editor typefaces. The Local Font page is the only settings preview changed for this feature; it shows the selected face in large and small samples before Apply. `HandwritingCanvasView` draws user stroke paths and contains no keyboard-font text. Icon/vector/path drawing, shortcut pictograms, Android framework inline autofill suggestions, and color emoji glyphs remain resource/platform-rendered. Popup menus in settings screens are outside the IME keyboard-rendering scope and keep platform menu typography.

## Selection, failure and reset

The picker uses `ACTION_OPEN_DOCUMENT`, `CATEGORY_OPENABLE`, and `EXTRA_LOCAL_ONLY`. Import streams to a temporary file under `noBackupFilesDir/custom_fonts`, caps input at 32 MiB while copying, validates sfnt signatures/table bounds and rejects TTC collections, WOFF/WOFF2, variable `fvar` tables, malformed directories, and unsupported signatures. It then asks Android to build the `Typeface`. Only a successful **Apply** atomically records and publishes the font. Parse, validation, Typeface, or persistence failures do not replace the active process snapshot. Cancel/exit discards only the preview. The active font and its state file are under `noBackupFilesDir`, so fonts are excluded from Android and JSON backups.

The standard button atomically stores standard mode, clears preview state, publishes a `null` typeface snapshot, and lets each view/paint restore its own baseline. A successful JSON settings import invokes this same standard reset only after JSON import succeeds; a failed JSON import leaves the active local font intact.
