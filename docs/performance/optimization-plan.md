# 改善の採用基準

1. ベースラインで P95 / P99 / 最大が跳ねるサンプルを特定する。まず T01〜T08 と T12〜T16 を含むクリティカルパスを確認する。
2. 再現性のある区間だけ変更する。候補計算が短くても公開後に遅れていれば、エンジン改変より先に表示経路を調べる。
3. 同じデバイス、ビルド、入力データ、設定、ウォームアップで再計測する。入力イベントは欠落させず、候補の内容・順序、エディタの確定結果、学習とユーザー辞書を比較する。
4. P95 / P99 / 最大の変化と、フレーム・メモリ・APK サイズへの副作用を記録する。改善を再現できない場合は挙動の変更を戻す。

Trace 修正は計測基盤に含める。高速化を主張する場合は基盤が同じ変更前後の結果を提示する。

英語の補完で同じ短い接頭辞が再入力されたときは、辞書探索の全結果を既存の辞書インスタンス内で再利用する。キーは接頭辞と件数上限の組み合わせ。最大32件、各結果は最大32候補。有効な候補のない入力や表記用の接頭辞を伴う入力は保存せず、探索はキャッシュのロック外で実行する。順位づけ、候補生成ルール、組み込み辞書は従来どおり。冷たい接頭辞とキャッシュ命中時の差を測る。 [実装](../../app/src/main/java/com/kazumaproject/markdownhelperkeyboard/converter/english/phrase/EnglishPhraseDictionary.kt#L56)
