# 学習した短い語の一般語への過剰な影響を抑える修正

検証日: 2026-11-10

## 基準と要件

実装前に upstream/dev を `pull --ff-only` し、`e0df25028948605d80640d6c42ccd816b9e943b6` が最新であることを確認した。修正ブランチは `codex/fix-learning-word-bias`。

既存の学習履歴を保持し、単独の人名入力では学習を効かせながら、短い読みの学習で別の一般語を過剰に押し下げないことを目的とする。zenz/Gemma を使わない通常変換経路を検証対象とした。

## 変更内容

- `LearningScorePolicy`: 初回の表示順位による減額を最大3000、再学習時の追加減額を500に制限する。
- 完全一致する学習語は保存済みのスコアを使い、単独入力の優先を維持する。
- 一般語の一部分として使う学習語は、元の辞書の同じ読み・表記・左右の品詞IDに一致するコストを基準に、優遇を最大500までとする。元のコストが得られない場合は6000を基準にする。
- 参照対象は変換で使用するシステム辞書、システムユーザー辞書、分類辞書、手動ユーザー辞書。同じ項目が複数ある場合は最小コストを使い、分類辞書の特殊表記やユーザー辞書の品詞変換も既存の変換処理に揃える。
- 辞書参照は部分的な学習語を使うときに遅延生成し、グラフ構築内だけで結果をメモ化する。
- 完全一致の学習を含むグラフから追加入力した場合は再構築する。強い完全一致スコアや、重複除去で置き換えられたノードを次の入力へ持ち越さない。

Room の Entity、DAO、データベース定義・バージョンは変更していない。既存スコア0の補正は変換時に行い、保存済みのスコア、利用回数、最終使用時刻、品詞情報等を書き換えない。

## RED / GREEN の証拠

1. 修正前に `LearningScorePolicyTest` と `LearnedConversionRegressionTest` を追加し、Gradle でコンパイル・実行した。4テスト中3件が想定した理由で失敗した。
   - 「けいさん」で、未学習時の先頭「計算」が「慧さん」に押し下げられる。
   - 大きな表示順位の初回減額が無制限に働き、期待7000に対して0になる。
   - 再学習時の減額が期待500に対して1500になる。
2. 再現テストを `test: reproduce learned-word bias in ordinary conversions` としてコミットした。
3. 最小修正と追加の境界・参照テストを入れ、関連5クラスの21テストがすべて通った。XMLの内訳は graph重複除去6、実辞書回帰3、辞書参照5、スコア方針4、既存学習セッション3。
4. アプリの変換セッション経由の回帰テストも追加し、単独入力と指定例が両バックエンド・3変換モード・文節処理ON/OFFで通ることを確認した。

各段階のログとXMLは、Git管理外の `build/kei-investigation/` に保存している。

## 回帰テストの内容

実辞書のスコア0の既存履歴を使い、「けい→慧」と「ちょう→徴」を検証した。「徴」は異なる品詞IDの2エントリを別々に試した。指定の読みは以下の8件。

| 読み | 保護する代表的な一般語候補 |
| --- | --- |
| けいさん | 計算、経産 |
| けいかいたいせい | 警戒態勢 |
| かんけいない | 関係ない、関係無い |
| ちょうし | 調子、銚子、長子 |
| けんちょう | 県庁、堅調、建長、健聴 |
| かちょうふうげつ | 花鳥風月 |
| ちょうかい | 懲戒、町会、朝会 |
| けいちょう | 傾聴、慶長、慶弔、経腸 |

未学習時の先頭候補を維持し、列挙した一般語のうち未学習時に上位4件にあったものが学習後も残ることを確認する。変換コアは N-best=4、beamWidth=20、N-gramと文節処理のON/OFFを組み合わせている。単独の「けい」「ちょう」では学習名が先頭になることも検査する。

さらに次を検証する。

- 辞書にない学習名「慧人」の単独入力、部分使用時の一般語保護、履歴保持。
- 同じ表記でも別の品詞の安いコストを誤って借用しないこと。
- 有効な複数辞書から最小の参照コストを選ぶこと。
- 分類辞書の表記上書き、手動ユーザー辞書の品詞、旧履歴の品詞未設定への対応。
- 追加入力・削除・複数文字の一括追加で、再利用したグラフの結果が毎回新しく構築した結果と一致すること。従来キャッシュとセッションキャッシュ、N-gram・文節処理の組み合わせを含める。
- すべての変換クエリ後も既存履歴が同一であること。テストDAOは書き込みを呼ぶと失敗する。
- アプリ側の `KanaKanjiConversionSession` を経由した候補追加・統合後の順位。従来／増分バックエンド、変換／予測／通常表示の3モード、文節処理ON/OFFで、単独名24比較と指定の一般語96比較を行う。

## 併せて見つかった upstream の既存失敗

既存の `KanaKanjiConversionSessionParityTest` 19件も実行したところ、18件は成功したが、`asciiInputKeepsHalfWidthUppercaseAcrossQueryModes` が「h8」に半角大文字候補「H8」がないとして失敗した。追加した学習セッション回帰テストは成功した。

切り分けのため修正ブランチのコードを保存し、基準の upstream `e0df2502` に戻して該当する英字テスト1件だけを実行した。同じ条件・同じメッセージで失敗したことを確認し、修正ブランチへ戻した。これは今回の学習修正による回帰ではない。英字変換の製品コードには変更を加えていない。

```text
LEGACY/false/NO_TAB_DEFAULT/false/h8: [h8, ｈ８, Ｈ８, h8, h8, h8, h]
```

## 適用範囲

元の辞書コストが得られない場合の6000は保守的な基準値であり、あらゆる未知語で順位不変を保証するものではない。完全一致の全文学習も引き続き尊重するため、過去に保存された全文の選択内容を推測して削除・無効化する処理は含まない。

GUI・実端末は起動していない。対象のアプリコードとユニットテストは Lite 版のGradleタスクでコンパイル・検証した。APK作成、インストール、push は行っていない。
