# 「ちょう→徴」の学習による一般語の順位変化

調査日: 2026-11-10

## 結論

指定の5入力で再検査した結果、「徴」を含む不自然な変換が上位に入り、一般的な候補が押し下げられる現象を確認した。「銚子」「堅調」「慶長」「慶弔」などが通常の N-best 上位4件から外れる条件も確認した。一方、未学習時の先頭候補は今回の40条件すべてで上位4件に残った。画面の全候補から消える現象を確認した、という意味ではない。

## 検査条件

- 前回と同じ upstream dev `e0df25028948605d80640d6c42ccd816b9e943b6` のソース・同梱辞書を使用。最新取得時点の main と関連実装・使用資産が同一であることは前回確認済み。
- zenz/Gemma はリンク・実行ともになし。
- 「ちょう」は小書き「ょ」を含む3文字として扱われることを確認。
- 未学習状態と、`ちょう→徴` の学習コストが下限0に達した状態を比較。
- N-best=4、beamWidth=20。文節処理 ON/OFF、システム N-gram ON/OFF を比較。
- 同じ「徴」に品詞情報の異なる2エントリがあるため、両方を別々に検査。
- 5入力 × 2品詞 × 2文節設定 × 2 N-gram設定 = 40条件。
- 追加で N-best=128、beamWidth=256 に広げた探索を実行し、押し下げられた候補が残るかを確認。
- 前回同様、実際の GraphBuilder / FindPath / 学習処理を JVM 上で実行した変換コアの検査。Android UI と最終候補の追加・統合は実行していない。保存先のみインメモリ DAO を使用。

## 文節処理なしの結果

システム辞書で先に現れる「徴」（左右ID 1841/1841、元の単語コスト6082）を、学習コスト0で適用した結果。N-gram は ON/OFF で同一だった。

| 読み | 未学習の上位候補 | 学習後の上位4件 | 未学習の先頭候補の変化 |
| --- | --- | --- | --- |
| ちょうし | 調子、銚子、長子、ちょうし | 徴し、徴師、徴士、調子 | 調子: 1位→4位 |
| けんちょう | 県庁、堅調、建長、健聴 | 件徴、権徴、県庁、県徴 | 県庁: 1位→3位 |
| かちょうふうげつ | 花鳥風月、課長風月、課長フウゲツ、か超風月 | 花鳥風月、か徴風月、化徴風月、か徴フウゲツ | 花鳥風月: 1位を維持 |
| ちょうかい | 懲戒、町会、朝会、鳥海 | 徴会、徴界、懲戒、徴回 | 懲戒: 1位→3位 |
| けいちょう | 傾聴、慶長、慶弔、経腸 | 系徴、型徴、軽徴、傾聴 | 傾聴: 1位→4位 |

学習した「徴」は入力先頭だけでなく、「けんちょう」「かちょうふうげつ」「けいちょう」の途中や末尾にも適用された。一般語への影響は、読みが3文字である今回の例でも発生している。

探索範囲を広げた場合、銚子は14位、堅調は7位、慶長は5位、慶弔は7位に現れた。今回のこれらの候補は辞書から削除されたわけではなく、学習語を含む経路に押し下げられていた。アプリは N-best 以外の候補も追加するため、この順位をそのまま画面全体の表示順位とは扱わない。

## 文節処理あり・別品詞の結果

同じ1841/1841の「徴」で文節処理を有効にすると、元の先頭候補は次の順位になった。

| 読み | 学習後の先頭 | 元の先頭候補の順位 |
| --- | --- | --- |
| ちょうし | 徴し | 調子: 2位 |
| けんちょう | 県庁 | 県庁: 1位 |
| かちょうふうげつ | 花鳥風月 | 花鳥風月: 1位 |
| ちょうかい | 懲戒 | 懲戒: 1位 |
| けいちょう | 軽徴 | 傾聴: 2位 |

別エントリ（左右ID 1923/1923、元の単語コスト6446）では、文節処理なしで「徴氏」が「調子」を、「徴海」が「懲戒」を上回った。文節処理ありでは5入力すべてで元の先頭候補を維持した。文字・読みだけでなく、確定した候補に付属する品詞情報も影響の強さを左右する。

## 2～3回の学習との関係

upstream の ConversionLearningSession → LearnRepository → LearnDao の実処理でも、固定した仮の表示インデックスを与えて3回の保存を検査した。元の単語コスト6082のエントリでは、コストは次のように変化した。

| 仮の表示インデックス（0始まり） | 1回目 | 2回目 | 3回目 |
| --- | --- | --- | --- |
| 0 | 6082 | 4582 | 3082 |
| 4 | 4082 | 2582 | 1082 |
| 10 | 1082 | 0 | 0 |
| 20 | 0 | 0 | 0 |

表示順位によっては2回の学習で最小コストに達する計算を確認した。ただし、実際の画面上の表示順位は観測していない。モデルでは毎回同じ候補スコア・仮の表示順位を与えて明示的選択として保存しており、実際の候補順位変化や先頭候補学習OFFによる保存対象の変化は再現していない。そのため、実機操作で必ず2回になるとは結論しない。
