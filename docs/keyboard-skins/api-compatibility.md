# Android 7〜9 のポップアップ互換性修正

## 問題と修正

レビュー対象 `1cf9a0ca7` は、最低対応 API 24 に対して API 29 で追加された
`PopupWindow.isLaidOutInScreen` / `setIsLaidOutInScreen` を無条件に呼んでいました。
クパチーノのフリック表示と、ウィンドウ外へ出る長押しガイドに影響します。
修正前の `:core:lintDebug` は、この問題を5箇所の NewApi エラーとして検出しました。

新しい内部ヘルパー `SkinPopupWindowCompat` で OS ごとの処理を分離しました。
API 29 以降は従来どおり画面座標で配置し、元の screen-layout 状態を保存・復元します。
API 24〜28 は専用 API を呼ばず、アンカーの画面座標とウィンドウ内座標の差を
引いてから `showAtLocation` / `update` に渡します。表示領域への収め方、固定フレーム、
入力を受け取らない設定、キーの入力判定は維持します。非公開 API は使用しません。

録画用ホストと既存の実機テストの Insets 取得も AndroidX へ変更し、
同じテストを Android 7 上で実行できるようにしました。

## 今回実行した検証

- 単体テスト82件成功（app 40件、core 42件）。追加8件は API 24・28・29・35で
  初回表示、方向変更、サイズ更新、状態復元、ガイドの破棄・再表示を確認します。
- `:core:lintDebug` 成功。API 互換性エラーは0件、既存警告は53件。
- 隔離した LiteStandardDebug と Android Test APK のビルド成功。
- Android 7 / API 24 エミュレーター：位置補正1件と既存ポップアップ3件が成功。
- Pixel 6 / API 37：位置補正と既存ポップアップの計4件が成功。
- Pixel 6 の本番 IME 通常表示：テンキー・QWERTY の各4スキン切り替え、
  計8シーケンス・68画面で候補、記号入力、デフォルト復帰を確認。
- 同じ本番 IME のフローティング表示でも8シーケンス・68画面が成功。
  テスト後に元の IME へ復元したことを確認しました。
- 位置補正テストは、原点を移動した小さな実ウィンドウで、フリックの固定フレームと
  はみ出す長押しガイドの画面座標を検査します。API 24でも実際の WindowManager を使用します。

Pixel 6 の初回試行は端末のスリープにより失敗しました。端末を復帰させた後の
成功ログを採用しています。また追加テストはレイアウト完了を待ってから座標を検査します。

[検証集計と APK・本番ソースの SHA-256](evidence/api-compatibility/validation.json) と
[実行ログ](evidence/api-compatibility/) を保存しています。
API 28・29 は Robolectric の検証であり、実機・エミュレーターでの確認とは区別します。
iOS の静止画・動画比較、過去の候補高さ全マトリクスは今回再実行していません。

デフォルト復帰時の状態復元を確認しました。公開 API・設定形式の変更はありません。
今回の互換性修正に未解決のマージ阻害指摘はありません。
